Every question, finding, or recommendation handed to the user should say **why** it's raised and **where** in the repo to read more: `file:line`, or transcript file plus speaker timestamp. Pushback on a client objective needs the strongest support: numbers reproducible from a script, the SOW's own language, and caveats stated up front.

**Why:** The user must be able to defend every element in front of the Tribe panel and asked for this explicitly ("so I know where to look in this repo"). Unsourced claims are indefensible under Q&A.

**How to apply:** Include *Why* and *Sources* lines by default. Put figures from our own analysis in a runnable script under `analysis/`, not only in prose. Mark our own cuts as *(extract)* to separate them from Meridian's stated figures.
